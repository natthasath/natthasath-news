⚙Technical Updates

  • MCP (Model Context Protocol) 2026-07-28: เผยแพร่เป็นสเปกฉบับสมบูรณ์เมื่อ 28 ก.ค. แทนที่รุ่น 2025-11-25 หลังผ่านช่วง release-candidate 10 สัปดาห์ตั้งแต่ 21 พ.ค. — เปลี่ยนจากโปรโตคอลแบบสองทิศทางที่มีสถานะ (stateful) เป็นโมเดล request/response แบบไร้สถานะ (stateless) ตัด handshake initialize และ Mcp-Session-Id ออก ทุกคำขอระบุตัวเองผ่าน _meta/HTTP header ทำให้ server รันหลัง load balancer ปกติบน infra แบบ serverless/edge ได้โดยไม่ต้องพึ่ง sticky session หรือ shared session store — client แคชผลลัพธ์ tools/list ได้ตาม ttlMs ที่ server กำหนด — เพิ่มกรอบส่วนขยาย (Extensions) อย่างเป็นทางการ 3 ตัว ได้แก่ MCP Apps (UI ที่ server render), Tasks (งานระยะยาว/async ย้ายออกจาก core) และ Enterprise Managed Auth (การจัดสรรสิทธิ์ทั้งองค์กรผ่าน IdP) — ยกเลิกการใช้งาน Roots, Sampling, Logging, HTTP+SSE transport และ Dynamic Client Registration (มีระยะเปลี่ยนผ่าน 12 เดือน) พร้อมยกระดับความปลอดภัยการยืนยันตัวตนผ่าน OAuth/OIDC — Anthropic ประกาศให้ Claude รองรับสเปกนี้ในวันเดียวกัน — MCP Blog (Official), Claude Blog (Official), VentureBeat
  • Cursor Start: แผนราคาใหม่สำหรับตลาดอินเดีย รวมสิทธิ์ใช้งาน Grok 4.5/Composer และ cloud agent (ดูหัวข้อ Tools & Apps) — Cursor Changelog

2. MCP 2026-07-28 (Stateless Core) — โครงสร้างพื้นฐาน AI agent ที่สเกลได้

ปัญหา
โปรโตคอล MCP แบบเดิมต้องรักษา session/stream ค้างไว้ระหว่าง client กับ server ทำให้ยากต่อการสเกลผ่าน gateway หรือ load balancer มาตรฐานบน infra แบบ serverless/edge
วิธีใช้
สเปกใหม่เปลี่ยนแกนหลักเป็นแบบไร้สถานะ (stateless) ตัด session handshake ออก เพิ่ม header-based routing ให้ gateway จัดเส้นทางได้โดยไม่ต้องแกะ JSON body และรองรับผลลัพธ์แบบแคชได้ผ่าน ttlMs
ประโยชน์
ผู้ให้บริการ MCP server ปรับสเกลระบบผ่านโครงสร้างพื้นฐานเว็บมาตรฐานได้ง่ายขึ้น ลดภาระการจัดการ session และเพิ่มความน่าเชื่อถือของระบบ agent ขนาดใหญ่ — MCP Blog

3. OmniRoute — จุดเชื่อมต่อ AI เดียวสำหรับผู้ให้บริการโมเดลหลายร้อยราย

ปัญหา
ทีมพัฒนาที่ใช้เครื่องมือ agent หลายตัว (Claude Code, Cursor, Copilot ฯลฯ) มักต้องจัดการ API key และ quota ของผู้ให้บริการโมเดลจำนวนมากแยกกัน ทำให้ยากต่อการสลับโมเดลหรือสำรองเมื่อโควตาหมด
วิธีใช้
OmniRoute เป็น gateway โอเพนซอร์สจุดเดียวที่เชื่อมต่อผู้ให้บริการกว่า 290 รายและโมเดลกว่า 500 ตัว พร้อมระบบ fallback อัตโนมัติเมื่อโควตาใกล้หมดและบีบอัด token เพื่อประหยัดต้นทุน
