⚠️✅ kubernetes/kubernetes v1.37.0 "Garhwal" — GA แล้ว
Go · Apache-2.0 · release v1.37.0 26 ส.ค. 2026 · ตั้งชื่อตามเทือกเขา Garhwal รัฐ Uttarakhand ประเทศอินเดีย

รุ่นนี้มีการเปลี่ยนแปลง 67 รายการ แบ่งเป็น 16 ฟีเจอร์ที่ขึ้นสถานะ Stable, 23 ฟีเจอร์ระดับ Beta, 27 ฟีเจอร์ใหม่ระดับ Alpha และ 1 การเลิกใช้งาน ไฮไลต์ฝั่ง Stable ได้แก่ metrics.k8s.io API ที่ขึ้น v1 หลังอยู่ Beta มาเกือบเก้าปี (ใช้งานโดย kubectl top และ HPA), kubectl get -o kyaml ที่ผ่าน conformance test ครบแล้ว, device taints/tolerations ของ Dynamic Resource Allocation และการ initialize resilient watch cache ซึ่งทีมงานระบุว่าเป็นชัยชนะด้าน operations ที่สำคัญที่สุดของรุ่นนี้ ช่วยให้ API server รับมือการกู้คืนคลัสเตอร์ขนาดใหญ่ได้ดีขึ้นด้วย backpressure แบบ HTTP 429

Breaking change ที่ต้องระวังก่อนอัปเกรด: ลบ kubelet configuration flag ที่เลิกใช้แล้วออกจริงพร้อม legacy fallback — คลัสเตอร์ที่ยังส่ง flag เหล่านี้จะสตาร์ทไม่ขึ้นหลังอัปเกรด, ต้องลบ object ประเภท scheduling.k8s.io/v1alpha2 ก่อนอัปเกรด, ค่า eventRecordQPS: 0 เปลี่ยนความหมายจาก "ปิดการทำงาน" เป็น "ไม่จำกัด", มีการเปลี่ยนแปลงด้าน SELinux ที่อาจทำให้ workload พังได้ และ ต้องใช้ containerd 2.0 ขึ้นไป ส่วนโหมด ipvs ของ kube-proxy ยังเดินหน้าสู่การเลิกใช้ต่อเนื่อง (วางแผนถอดออกใน v1.43)

⚠️ Breaking Changes

kubernetes/kubernetes v1.37.0
GA 26 ส.ค. 2026
  • Breaking: ถอด kubelet configuration flag ที่เลิกใช้แล้วออกจริงพร้อม legacy fallback — คลัสเตอร์ที่ยังส่ง flag เดิมจะสตาร์ทไม่ขึ้น
  • Migration: ต้องลบ object scheduling.k8s.io/v1alpha2 ทั้งหมดก่อนอัปเกรด
  • API Change: eventRecordQPS: 0 เปลี่ยนความหมายจาก "ปิด" เป็น "ไม่จำกัด"
  • Requirement: ต้องใช้ containerd 2.0 ขึ้นไป
  • Deprecated: kubectl run --filename, static pod อ้างอิง Secret/ConfigMap ไม่ได้อีกต่อไป, โหมด ipvs ของ kube-proxy (วางแผนถอดออกใน v1.43), การรองรับ cgroup v1

🧭 สรุปแนวโน้ม Open Source Ecosystem

หนึ่ง — โครงสร้างพื้นฐานระดับ orchestration กำลังปิดรอบใหญ่พร้อมกัน การที่ Kubernetes v1.37 GA มาพร้อม breaking change ชุดใหญ่ที่สุดในรอบหลายรุ่น (ถอด kubelet flag เดิม, บังคับ containerd 2.0) หมายความว่าทีม platform engineering ทั่วโลกต้องวางแผนอัปเกรดอย่างระมัดระวังในไตรมาสนี้ ไม่ใช่แค่กด upgrade ตามปกติ

สอง — ความปลอดภัยกำลังกลายเป็นเดิมพันของทั้งผู้ให้บริการรายใหญ่และ ecosystem การที่ Next.js ต้องเลื่อนแพตช์ให้เร็วขึ้นเพื่อปิดช่องโหว่ RCE ระดับ 9.5 และ Anthropic ทุ่ม 35 ล้านดอลลาร์ให้ open source security ในสัปดาห์เดียวกัน สะท้อนว่าความปลอดภัยของ supply chain ไม่ใช่ประเด็นข้างเคียงอีกต่อไป แต่เป็นเดิมพันหลักของทั้งวงการ โดยเฉพาะเมื่อเวิร์ม ChainDrop ยังไม่ปิดเคส

สาม — "ความจำของ agent" กลายเป็นสมรภูมิใหม่แทนที่ตัว agent loop เอง openhuman, TencentDB-Agent-Memory และคลัง skill เฉพาะทางต่าง ๆ ต่างพุ่งเป้าไปที่การทำให้ agent จำและเรียนรู้ข้ามเซสชันได้ดีขึ้น ขณะที่ apache/maka เลือกแก้ปัญหาเดียวกันด้วยแนวทาง append-only log ที่ตรวจสอบย้อนกลับได้ ชี้ว่าตลาดยังไม่ตกผลึกว่าวิธีไหนจะชนะ

สี่ — ระบบนิเวศปลั๊กอิน agent กำลังรวมศูนย์เข้าสู่ curated marketplace ทั้ง Anthropic ผ่าน claude-plugins-community/official และ Cursor ผ่าน cursor/plugins กำลังสร้างโมเดลตรวจสอบและอนุมัติปลั๊กอินแบบเดียวกับ app store ซึ่งต่างจากยุคก่อนหน้าที่ปลั๊กอินกระจัดกระจายอยู่ตาม repository ของแต่ละคน

เทคโนโลยีที่ควรจับตาในสัปดาห์หน้า ได้แก่ ผลกระทบจากการอัปเกรด Kubernetes v1.37 ในองค์กรจริงและปัญหาที่อาจเกิดจาก containerd 2.0, อัตราการอัปเกรด Next.js หลังแพตช์ความปลอดภัยฉุกเฉิน, รายชื่อผู้รับทุนนำร่องรอบแรกของ Anthropic 0xDAF, ความคืบหน้าของ apache/maka ในการรองรับแพลตฟอร์มอื่นนอกเหนือจาก Apple Silicon และพัฒนาการต่อเนื่องของเวิร์ม ChainDrop / Shai-Hulud ในระบบนิเวศ npm
